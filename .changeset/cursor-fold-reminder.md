Cursor gets a fold reminder. Cursor's `stop` hook cannot block, so with `@ctxo/domain` `ctxo init --domain` (Cursor selected) now registers `ctxo domain-cursor-hook` in `.cursor/hooks.json` for `beforeSubmitPrompt` and `stop`, merged into the hooks already there. The first prompt of a conversation records where it starts; every prompt gets exactly `{"continue":true}` (also without `@ctxo/domain` and on any error), and a repeat prompt answers without loading the module or running git. On a `stop` with `status: "completed"` the reminder runs the Claude Code fold guard's own decision and, when the guard would block, prints `{"followup_message":"ctxo domain reminder: ..."}` with the guard's reason. At most once per conversation (else per generation, else per 10 minutes), quiet while a follow-up runs, with `domain.guard.enabled: false` and on any error; it never blocks and always exits 0; an aborted or errored stop prints nothing. `domain.guard.enabled: false` also keeps init and doctor from adding the entries. `ctxo doctor` reports a missing, duplicated or unreadable reminder entry under `domain_agent_setup` when `.cursor/` exists, and `ctxo doctor --fix` now repairs the domain agent setup (loader rules, the Claude Code guard hooks, the Cursor reminder, the `ctxo-domain-fold` skill), keeping other hooks and never writing an unreadable file. Module API: `CtxoModuleRegistration.doctorFixes` (`ModuleDoctorFix`, `DoctorFixContext`).
