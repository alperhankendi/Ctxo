`ctxo watch` now refreshes the domain artifacts. With `@ctxo/domain` installed, watch runs the domain index pass (the one `ctxo index` runs) after the re-index of the changed files, so `graph.json`, `maturity.json`, `shadow-candidates.json`, `contexts.json` and `boundaries.json` follow your edits and the domain tools stop answering `stale: true`. A registry, card or glossary edit runs the pass after a quiet period of 1 s, or twice the last pass when that is longer; changed source files run it once `watch.snapshotMinFileChanges` of them are pending, 5 s after the last event; a due pass is never postponed more than 30 s; at start, one pass runs only when the graph is stale. For the same index at the same commit the pass writes the bytes `ctxo index` writes; the change-log fields (moved files, discovery, history) keep the values of the last `ctxo index`. A registry created while watch runs gets no pass (no facts were requested): run `ctxo index` and restart watch. Passes never overlap, a failing pass is logged and watch goes on, and without `@ctxo/domain` watch behaves as before. The stale hints now name the watch refresh. `shadow-candidates.json` now writes fact `detail` keys in codepoint order, so a full and an incremental run give the same bytes. Module API: `classifyWatchPath(path, indexed)`, `watchArtifactsStale()` and `IndexPassContext.factsRequested`.
