# Changelog

All notable changes to Ctxo MCP Server are documented in this file.

From 0.7.0 onwards, Ctxo ships as a pnpm monorepo with five packages. Per-package changelogs are generated by the changesets bot starting at 0.7.1. This root CHANGELOG covers the project-level milestones.

## [Unreleased]

**Architectural intelligence: community detection, drift, and boundary violations.**

### Added

- `@ctxo/cli` community detection pipeline (Louvain via `graphology` + `graphology-communities-louvain`)
  running during `ctxo index` Phase 2c, after co-change aggregation and before JSON write. Produces
  `.ctxo/index/communities.json` (committed) plus rotating `.ctxo/index/communities.history/` (last 10
  snapshots). Snapshots also refresh during `ctxo watch` (debounced 5s window).
- `get_architectural_overlay` tool gains a `mode` parameter (`regex` | `communities` | `both`,
  default `both`) and a new `communities` section surfacing data-driven clusters, god nodes,
  modularity, cross-cluster edge count, and edge-quality tier.
- `get_blast_radius` response adds `byCluster` breakdown + `crossClusterEdges` count +
  `multiClusterHint` when a change impacts 3+ clusters — multi-team review signal.
- `get_why_context` response adds `driftSignals` (cluster transitions for the queried symbol) with
  `confidence` (high/medium/low) and actionable hints when snapshot history is thin.
- `get_pr_impact` response adds `boundaryViolations` (edges between historically isolated clusters)
  and `clustersAffected` breakdown.
- `ctxo init` warns when hooks are declined and points to watch/CI alternatives, so users know
  drift/boundary signals depend on snapshot cadence.
- `ctxo index --skip-community` flag to opt out of community computation.
- `ctxo init` now supports **Gemini CLI** and **Continue** as installable AI tool targets.
  - Gemini CLI: writes `GEMINI.md` rules (append mode) and registers the ctxo MCP server at
    `.gemini/settings.json` (`mcpServers` key).
  - Continue: writes `.continue/rules/ctxo.md` rules and registers the ctxo MCP server at
    `.continue/mcpServers/ctxo.json` (each MCP server is a standalone file under
    `.continue/mcpServers/`).
  - Brings the supported AI tool list to nine: Claude Code, Cursor, GitHub Copilot, Windsurf,
    Antigravity, Augment, Amazon Q, Gemini CLI, Continue.
- `ctxo update` — self-update mechanism. Checks `registry.npmjs.org` for newer versions of
  `@ctxo/cli` and every installed `@ctxo/lang-*` / `ctxo-lang-*` plugin, then either runs the
  local install or prints the command for the user to run.
  - Per-package channel detection: alpha installs stay on alpha, stable stays on stable. Falls
    back to `latest` with explicit `(latest)` annotation when the chosen channel is not
    published.
  - Auto-execute vs print fallback: runs the install when the project has `@ctxo/*` in its
    `package.json`; otherwise prints the global install command instead of mutating an
    unrelated workspace.
  - Flags: `--check` (check only, exit 0), `--print` (never execute), `--global` (force global),
    `--json` (single-document machine-readable output), `--pm <npm|pnpm|yarn|bun>` (override
    manager), `--force` (bypass CI lockfile guard).
  - Rejects npm version specifiers containing shell metacharacters before passing them to the
    package manager (defence-in-depth against a hostile registry response).
  - Spec: `docs/superpowers/specs/2026-05-15-ctxo-update-design.md`.
- **Co-change engine (#157).** `ctxo index` builds `co-changes.json` from one `git log` pass with its
  own window, independent of `--max-history`. New `cochange:` config in `.ctxo/config.yaml`
  (`maxCommits` 2000 or `all`, `since`, `maxFilesPerCommit` 30, `minShared` 2, `include`, `exclude`)
  and overrides `ctxo index --cochange-commits <n|all>` and `--cochange-since <duration>`. Merge
  commits are excluded from the log, commits above `maxFilesPerCommit` are skipped and counted
  (`massSkipped`), renames are followed, and the applied window is recorded in the file under
  `window`. `cochange.exclude` also vetoes files added by `cochange.include`.
- **Incremental indexing (#157).** `ctxo index --files <path...>` and `ctxo index --commit <rev>`
  re-index part of the index and compute co-change, communities, the snapshot, the drift and
  boundary artifacts and the SQLite cache from the merged index. `--file` stays as an alias of
  `--files`.
- **Post-commit hook v2 (#157).** `# ctxo-start v2` runs `ctxo index --commit HEAD` once per commit,
  guarded by `[ -d .ctxo ]`. `ctxo init` and `ctxo doctor --fix` upgrade older blocks in place,
  collapse duplicate blocks, and follow `core.hooksPath`. When `core.hooksPath` comes from the global
  or system git config (a directory shared by every repository), they write nothing and print the
  blocks to add by hand. Detecting the scope needs git 2.26 or newer.
- `git_hooks` doctor check: warns on a missing, outdated or duplicated post-commit block (#157).
- `get_blast_radius` and `ctxo blast-radius` return `coChangedFiles`: up to 10 files that co-change
  with the target's file (frequency of at least 0.5) but have no dependency path to it. Informational:
  not counted in tiers, risk scores or the gate. `coChangeFrequency` is now filled on impacted
  symbols, and `get_context_for_task` entries that depend on the symbol carry an optional
  `confidence` tier (#157).
- `distinctCommits` on `driftSignals`, `boundaryViolations` and their committed artifacts (#157).
- `ctxo <command> --help` and `-h` print the help for every subcommand without running it (#157).
- ADR-016: co-change engine, incremental indexing and snapshot policy.
- **Contexts view (#156 Phase 1).** `ctxo index` writes `.ctxo/index/contexts-view.json`: candidate
  bounded contexts from file-level Louvain over a blend of dependency and co-change edges, with hub
  files damped. Each candidate has a suggested label, fingerprint, cohesion, top terms,
  cross-candidate edges and co-change pairs; type names whose shapes differ between candidates are
  listed as collisions. The view is recomputed on every index run that re-indexes files (and on every post-commit
  hook run), skipped by `--skip-community`, and not refreshed by `ctxo watch`.
- `get_architectural_overlay` gains `mode: "contexts"` (summary of every candidate, with hubs and
  collisions capped at 50) and a `candidate: <id>` argument that returns one candidate in full.
  `candidates` joins the truncatable fields of the response envelope.
- `ctxo contexts` prints the candidates as a table (stderr); `ctxo contexts --json` prints the full
  `contexts-view.json` (stdout).
- Config: `communities:` (`resolution`, `godNodeMinBridged`, `godNodeMaxResults`), `contextsView:`
  (`weights`, `exclude`, `hubs`, `resolution`, `minCandidateFiles`, `technicalTerms`) and
  `index.tests` (extra test-file globs). One shared test-file classifier with default globs for
  TypeScript, Go, C#, Java and Python now backs the contexts view.
- ADR-016 addendum: contexts view defaults and their evidence.
- **Plugin protocol v2 (#156 Phase 1).** `@ctxo/plugin-api` adds the symbol kinds `table`, `view` and
  `procedure`, the edge kinds `reads`, `writes` and `executes`, and `DATA_RESOURCE_KINDS`; typed symbol
  `annotations` (`SymbolAnnotation`: `name`, `args`, `named`); the facts protocol (`FACT_KINDS`,
  `CodeFact`, an optional `extractFacts`), called only on request; host capabilities
  (`PluginCapabilities` with `facts` and `sqlCallSites`, on `PluginContext.capabilities`); and
  `SUPPORTED_API_VERSIONS = ['1', '2']`. The CLI loads plugins that declare either version. Annotations
  and facts live in the JSON index only.
- **`@ctxo/sql-extract`**: a zero-dependency T-SQL tokenizer with access and definition recognizers
  (`extractSqlAccesses`, `extractSqlDefinitions`), shared by the SQL plugin and, later, by other
  language hosts. A conformance corpus in `packages/sql-extract/corpus` keeps it in agreement with the
  C# side.
- **`@ctxo/lang-sql`**: a protocol v2 plugin for `.sql` files (T-SQL). Tables, views, procedures and
  functions become symbols (tables carry a `columns` annotation), and their bodies give `reads`,
  `writes` and `executes` edges to canonical `schema.name` targets (default schema `dbo`).
  `ctxo install sql` (alias `tsql`) installs it, and language detection, `ctxo doctor` and
  `ctxo index --install-missing` suggest it when the repository has at least 5 `.sql` files that are
  also at least 2% of its files.
- C# attribute annotations: `@ctxo/lang-csharp` reports the attributes written on each symbol in both
  the Roslyn and the tree-sitter tier (20 per symbol, 10 positional entries and 10 named entries plus
  the reserved `type`, 200 characters per value; a source argument named `type` is dropped in both
  tiers). The Roslyn tier keeps constant arguments, including strings, enum constants, `typeof(T)`
  and arrays; the tree-sitter tier keeps literal arguments only (strings, numbers, booleans).
- SQL edges at C# call sites: with `@ctxo/lang-sql` installed, the Roslyn helper parses constant SQL at
  known ADO.NET (`SqlCommand`, `CommandText`, `CommandType.StoredProcedure`), Dapper, `SqlBulkCopy` and
  EF Core raw SQL call sites with ScriptDom and adds `reads`, `writes` and `executes` edges from the
  calling method. Only compile-time constants count.
- Dapper `CommandDefinition` is a known call site: its constructor's `commandText` is parsed, and a
  `commandType` argument of `CommandType.StoredProcedure` (named or positional) makes it a procedure
  name (#156).
- Contexts view: `dataResources` (every table or view a candidate reads or writes, with access modes,
  writers, the owning candidate and an `external` flag) and `sharedTables` per candidate (resources of
  two or more candidates). `get_architectural_overlay` `mode: "contexts"` gives counts in the summary
  (`sharedTableCount`, `dataResourcesTotal`, `sharedResourcesTotal`, `externalResourcesTotal`) and up to
  15 `sharedTables` and 15 `dataResources` in the `candidate: <id>` detail, fewer when the response
  limit requires; `ctxo contexts` lists the shared tables and `ctxo index` prints their count.
- Config: `index.facts` (request code facts) and `contextsView.weights.data` (default 0: shared tables
  are a finding, not a clustering weight).
- `csharp_tier` doctor check: reports the C# tier and warns when the Roslyn helper cannot restore its
  NuGet packages, with the first error line and a fix hint.
- Test files are recognised by test-framework annotations (`Fact`, `Theory`, `SkippableFact`,
  `SkippableTheory`, `Test`, `TestCase`, `TestCaseSource`, `TestFixture`, `TestMethod`,
  `DataTestMethod`, `TestClass`). An annotated file is a test file whatever its path; once C#
  annotations exist in the index, a file matched only by `**/*Test.cs` or `**/*Tests.cs` needs a test
  annotation to count as a test.
- ADR-017: plugin protocol v2, data coupling and facts, and the `@ctxo/sql-extract` dependency
  exception. Feature doc: `docs/features/domain-knowledge.md`.
- **Tiered agent rules (#159).** Claude Code gets a compact 4-line ctxo block in `CLAUDE.md` when the
  safe-edit guard hook, all three skills and an enabled gate are in place; every other client, and
  Claude Code without them, gets the full block. The tier is chosen from what is on disk after the
  skills and guard are installed. A rules file several clients share (an `AGENTS.md` or `GEMINI.md`
  linked to `CLAUDE.md`) gets the full block and settles in one run.
- **Versioned rules markers (#159).** Blocks sit between `<!-- ctxo-rules-start v<version> -->` and
  `<!-- ctxo-rules-end -->` (the rules template version) and are replaced in place, together with
  unversioned blocks and the old unmarked body. A block from a newer ctxo, a start marker without
  an end marker, or an end marker without a start marker leaves the file unchanged with a warning.
- **Formatter-stable rules and skills (#159).** The blocks and the bundled skills are written in
  Prettier's layout and compared with formatting ignored (line endings, BOM, trailing whitespace,
  blank lines, table padding, line wrapping), so a markdown formatter and ctxo never rewrite each
  other, and a formatted compact block no longer reads as an opt-out.
- **Versioned skills (#159).** Each bundled skill ends with `<!-- ctxo-skill v<version> -->`. A skill
  from a newer ctxo is left alone with a warning and is not reported as outdated.
- **No silent opt-out (#159).** `ctxo init` (including `--only rules`, `--rules` and the dry run) and
  `ctxo doctor --fix` leave a pre-tier or compact block unchanged while the guard or skills it
  expects are missing and not declined, and say so: `left unchanged until the guard and skills are
  installed; run "ctxo init --only rules,skills,guard" or "ctxo doctor --fix"`.
- **Init parts (#159).** `ctxo init --only <parts>`, `--skip <parts>` and `--no-guard` over the parts
  `rules`, `skills`, `guard`, `mcp`, `git-hooks` and `config`, run in one order for the interactive,
  non-interactive and dry-run paths. `--only` cannot be combined with `--skip` or `--rules`.
- `ctxo init --dry-run` lists every file init would create or change, with `would create`,
  `would update` or `unchanged`, and writes nothing (#159).
- Doctor checks `ai_rules`, `skills` and `claude_guard_hook` (#159). `ctxo doctor --fix` installs
  missing or outdated skills and the guard, then re-renders the rules blocks in the tier that now
  applies. It installs nothing the user declined, never writes an unreadable `.claude/settings.json`,
  and holds the `CLAUDE.md` block until the guard and skills are in place.
- ADR-015 amendment: tiered rules (#159).

### Changed

- `IStoragePort` gains `readCommunities`, `writeCommunities`, `listCommunityHistory`. Backed by new
  `CommunitySnapshotWriter` under `adapters/storage/`. Backwards-compatible: when no snapshot
  exists, tools degrade to prior behaviour (regex overlay, blast radius without cluster breakdown,
  etc.).
- `response-envelope` truncation whitelist now covers `clusters` and `clustersAffected`.
- Drift and boundary confidence count distinct commits instead of snapshot files (fewer than 3 is
  `low`, 3 to 6 `medium`, 7 or more `high`). `snapshotsAvailable` stays for compatibility. The hints
  no longer suggest `ctxo index --check`, which records no snapshot (#157).
- History keeps one community snapshot per commit. The first write after upgrading removes older
  same-commit duplicates from `communities.history/` (this repository went from 11 files to 5);
  no information is lost (#157).
- Co-change reaches every blast-radius path: `get_blast_radius`, `get_pr_impact`,
  `get_context_for_task`, `ctxo blast-radius`, the safe-edit gate hook and `ctxo gate --preview`.
  The gate counts `confirmed + likely` dependents, so it may fire somewhat more often (#157).
- A full `ctxo index` uses only the files it discovers and removes index entries of deleted or
  newly ignored sources, never those of skip-worktree paths (sparse checkout). In a sparse
  checkout, files outside the cone are absent from the co-change matrix (#157).
- `intent[]` follows renames, so `ctxo verify-index` reports files with a rename in their history as
  `STALE` until the next `ctxo index` after upgrading (#157).
- `ctxo index --max-history` controls per-file intent depth only; the co-change window has its own
  settings (#157).
- `reads`, `writes` and `executes` are `confirmed` blast-radius tiers, so the safe-edit gate also
  guards heavily used tables and procedures (#156).
- C# users see a one-time change in their committed index JSON on the first re-index after upgrading:
  annotations are always on (#156).
- **Run a full `ctxo index` after upgrading `@ctxo/lang-csharp`.** An incremental run (`--files`,
  `--commit`, and so the post-commit hook) annotates only the files it re-indexes, but the contexts
  view already counts the index as annotated: until a full run, name-only `*Test.cs` / `*Tests.cs`
  matches that were not re-indexed show up as production files. A bare capital `Tests/` or `Test/`
  folder is not a default test glob (`**/tests/**` is case-sensitive); add it to `index.tests` (#156).
- When several files define the same table, view or procedure, data references resolve to a
  definition outside test files (default test globs), then outside `docs`, `doc` and
  `documentation` folders, then to the codepoint-smallest symbol ID. `index.tests` is not consulted;
  `index.ignore` can drop docs or test copies (#156).
- Contexts view: a stored procedure's reads and writes count for the candidates that execute it,
  decided by its canonical name, and no longer for the candidate that holds the script. A procedure
  that no candidate executes still credits its own candidate. When several files define it, the
  bodies of every production copy count (the winner's alone when no copy is production), and docs
  and test copies of a procedure that has a production copy add nothing (#156).
- `get_logic_slice` returns symbol `annotations` at `L4` only; `L1` to `L3` and `get_context_for_task`
  leave them out, so attribute arguments and column lists no longer crowd out dependencies (#156).
- Data edges stay out of symbol-level communities, god nodes, cross-cluster counts and boundary
  violations; data coupling is reported by the contexts view (#156).
- Symbols in `.sql` files are never reported as dead code (#156).
- UTF-16 source files with a byte order mark (as SSMS saves SQL scripts) are decoded by `ctxo index`,
  `--check` and `ctxo watch`. Their content hash changes once, so `ctxo index --check` reports them
  stale until the next `ctxo index`; UTF-8 files are unchanged (#156).
- The Roslyn helper now restores `Microsoft.SqlServer.TransactSql.ScriptDom` from NuGet for every C#
  user. When the restore or build fails (for example a private or offline feed without the package),
  `@ctxo/lang-csharp` falls back to the tree-sitter tier: symbols and attribute annotations (literal
  arguments only) are kept, Roslyn-tier details and SQL call-site edges are lost, `ctxo index`
  reports the syntax tier and `ctxo doctor` warns (#156).
- The Roslyn helper declares `RollForward` `Major`, so it can roll forward to a newer major .NET
  runtime when no .NET 8 runtime is installed. The built helper has been run with
  `dotnet exec --fx-version` on .NET 8, 9 and 10 (#156).
- The MCP descriptions of `get_blast_radius` (tiers by edge kind, every symbol kind), `find_dead_code`
  (`.sql` symbols) and `get_architectural_overlay` (data lists) match what the tools do (#156).
- The full rules block opens with a narrowed rule: "For structural questions (dependencies, impact,
  history), use ctxo tools first; reading a file to see its contents needs no index call." Step 3
  reads "Only then edit the source", and the block has no em dashes (#159).
- `ctxo-understand` carries a question-to-tool selection guide for all 14 tools, and its description
  no longer tells the agent to call ctxo before reading source (#159).
- `ctxo init -y` without `--tools` sets up all nine AI tools, the same set `--dry-run` previews; it
  used to select none (#159).
- `ctxo init --rules` is deprecated: it now means `--skip git-hooks,guard`, still skips the plugin
  step, and prints a notice (#159).
- Rules files that init used to overwrite whole (`.cursor/rules/ctxo.mdc`, `AGENTS.md`,
  `.github/copilot-instructions.md` and the rest) keep the user's content outside the ctxo block
  (#159).
- `ctxo doctor --fix` replaces an edited ctxo skill with the bundled copy; copy a customised skill
  under another name (#159).
- Init output drops the em dash: `[ctxo] ✓ <file> (<created|updated|unchanged>)` (#159).

### Fixed

- The v1 post-commit hook (`ctxo index --file` per changed file) no longer empties
  `co-changes.json`: this repository's committed matrix had gone from 1126 entries to 0 (#157).
- `--file` no longer empties the SQLite cache, builds `boundary-violations.json` from a one-file
  graph, or stamps the snapshot with the wrong commit SHA (#157).
- One commit can no longer fill the snapshot history: the v1 hook wrote up to 10 snapshots for one
  SHA in about 11 s (#157).
- `ctxo index --help` and `ctxo init --help` ran the command instead of printing help (#157).
- The post-commit hook could not be upgraded once installed and ignored `core.hooksPath` (#157).
- A dependent inside the target's own file no longer picks up an unrelated co-change entry when
  tiering blast radius (#157).
- Docs, hints and the declined-hooks advice claimed `ctxo index --check` builds snapshot history (#157).
- A full `ctxo index` dropped source files with non-ASCII names (git prints them quoted), so a
  full run and a `--commit` run disagreed, `ctxo doctor` listed their entries as orphans and
  `ctxo doctor --fix` deleted them. `ctxo status` and language detection read the same names (#157).
- Drift events, boundary violations and god nodes are sorted by code point, not by the machine's
  locale, so `communities.json` and the artifacts next to it are the same on every machine (#157).
- With `CTXO_HTTP_PORT` exported, `ctxo <command>` started the HTTP server instead of running, so
  the post-commit hook (`ctxo index --commit HEAD`) never returned and `git commit` hung. The
  variable now applies only when `ctxo` runs without arguments; `ctxo --http` without `--port`
  now listens on its default port 3001 instead of failing on an invalid port (#157).
- `get_architectural_overlay` `mode`, `get_ranked_context` `searchMode` and `search_symbols` `mode`
  were accepted by the handlers but missing from the registered tool schemas, so MCP clients could
  never send them. They are registered now, and a test compares both schemas (#156).
- God nodes with equal scores are ordered by code point, not by the machine's locale (#156).
- A C# repository with a lone `.csproj` and no solution file now indexes in the Roslyn tier: the
  helper opened the project as a solution and found no symbols (#156).
- A failed Roslyn helper restore or build no longer leaves every C# file with zero symbols; the plugin
  falls back to tree-sitter (#156).
- `ctxo watch` no longer hangs when the Roslyn helper exits before it is ready (#156).
- A huge `.sql` file (a data dump or seed script) no longer crashes `ctxo index` or the post-commit
  hook by exhausting memory: `@ctxo/lang-sql` skips `.sql` files larger than 5 MiB, with one warning
  per file (`skipped <file>: <n> MiB is over the 5 MiB SQL size limit`) and no symbols or edges for
  it (#156).
- `ctxo watch` no longer writes a C# file with zero symbols after the Roslyn keep-alive shut down for
  inactivity or crashed: the next re-index restarts it once, and falls back to tree-sitter if the
  restart fails (#156).
- The impact tools agree for every copy of a table, view or procedure that several files define, and
  for its 2-part ID (`dbo.loans::table`): `get_blast_radius`, `find_importers` (direct and
  transitive), `get_pr_impact`, `get_context_for_task`, the safe-edit gate and `ctxo blast-radius`
  report the dependents of the winning definition. A non-winning copy, such as a
  `CREATE OR ALTER PROCEDURE` in a new migration, used to report zero dependents, and a 2-part ID
  found the symbol but no dependents or importers. `get_logic_slice` now walks a 2-part procedure's
  dependencies (each copy's full ID keeps its own body), and `get_why_context` reads the winner's
  file for a 2-part ID (#156).
- A new `CLAUDE.md` (or `GEMINI.md`) was written without markers, so the next `ctxo init` appended a
  second ctxo block (#159).
- Rules files written in create mode always reported `updated`, even when nothing changed (#159).
- A corrupt or oddly shaped `.claude/settings.json` (invalid JSON, `null`, an array, `PreToolUse`
  as an object) was overwritten or crashed `ctxo init`. It is now left unchanged with a warning, and
  `ctxo doctor` reports it (#159).
- An MCP config whose root or server map is not an object crashed `ctxo init` (a string
  `mcpServers`) or was written back without the ctxo entry (an array root). It is now treated like
  corrupt MCP JSON and overwritten (#159).

### Compatibility

- Older CLIs skip `@ctxo/lang-sql` (protocol v2) with a warning, and drop the new symbol and edge kinds
  with a warning when they read an index written by this version. `@ctxo/lang-sql` needs a CLI that
  accepts protocol v2.
- The official plugins accept `@ctxo/plugin-api` `^0.7.3 || ^0.8.0 || ^0.9.0` as a peer;
  `@ctxo/lang-sql` accepts `^0.8.0 || ^0.9.0`. Existing plugins stay on protocol v1, so upgrading one
  never breaks an older CLI.

### Removed

- The unused `fuzzy` parameter of `get_ranked_context`. Typo correction stays automatic in `fts`
  mode and is reported in `fuzzyCorrection`; a client that still sends `fuzzy` gets a normal answer (#156).

## [0.8.0-alpha.0] - 2026-04-13

**Go full-tier semantic analysis via `ctxo-go-analyzer` binary.**

### Added

- `@ctxo/lang-go` upgraded to full tier: ships a standalone Go binary
  (`packages/lang-go/tools/ctxo-go-analyzer/`) that uses `go/packages`,
  `go/types`, `golang.org/x/tools/go/ssa`, and `golang.org/x/tools/go/callgraph/cha`
  to produce semantic edges (`calls`, `uses`, `implements`, `extends`) with
  cross-package symbol-id resolution
- Generic instantiations preserve `typeArgs` metadata on uses/calls edges
  while collapsing to a single edge per generic type (ADR-013 §4 Q4)
- Reflect-safe heuristics (reflect.TypeOf / reflect.ValueOf / reflect.New,
  json.Marshal / Unmarshal / NewDecoder / NewEncoder) prevent false-positive
  dead-code reports
- New `dead` JSONL record from the binary listing unreachable
  function/method symbol ids; `GoAnalyzerAdapter.getDeadSymbolIds()` exposes
  it for `find_dead_code`
- `GoCompositeAdapter` picks full-tier when Go ≥ 1.22 + analyzer binary
  available; falls back to tree-sitter syntax tier otherwise
- Lazy binary build into `~/.cache/ctxo/lang-go-analyzer/<sourceHash-goVersion>/`
  on first use (ADR-013 §4 Q2)
- Test fixture under `packages/lang-go/test-fixtures/sample-module/` exercising
  every edge kind, generics, reflect, and dead-code cases
- ADR-013 documents the decision and four resolved open questions

### Changed

- `@ctxo/lang-go` plugin tier is now `'full'` (was `'syntax'`)
- Removed exported-only filter from the tree-sitter Go adapter so unexported
  symbols flow through (matches behavior of the new analyzer layer)

### Notes

- ADR-013 originally specified RTA for reachability; switched to CHA because
  `rta.Analyze` panics on generic code in current `golang.org/x/tools`. CHA
  is more conservative (over-approximates reachability) which is the safer
  choice for dead-code detection.
- `ctxo-go-analyzer` binary is built lazily on first use; consumers need
  Go ≥ 1.22 on PATH. `ctxo doctor` surfaces missing toolchain.

## [0.7.0] - 2026-04-13

**Architecture: major refactor to plugin-based language support.**

### Added

- `@ctxo/plugin-api` — stable plugin protocol v1 with `CtxoLanguagePlugin`, `ILanguageAdapter`, `PluginContext`, `IWorkspace` contracts
- `@ctxo/lang-typescript` — extracted TypeScript / JavaScript plugin (ts-morph, full tier)
- `@ctxo/lang-go` — extracted Go plugin (tree-sitter, syntax tier)
- `@ctxo/lang-csharp` — extracted C# plugin (Roslyn full tier + tree-sitter syntax fallback, ships the .NET launcher)
- `ctxo install [<lang>...]` command with npm/pnpm/yarn/bun resolver, corepack `packageManager` field detection, and monorepo-aware lockfile walk-up
- `ctxo --version --verbose` / `--json` — reports cli + plugin API version + installed plugins + runtime
